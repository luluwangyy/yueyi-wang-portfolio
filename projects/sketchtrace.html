SketchTrace

Making complex creative code easier to understand.

SketchTrace transforms creative JavaScript into an interactive learning workspace, combining source code, a live preview, and a clickable system map that links directly back to relevant lines of code.

The Problem

Creative coding projects can look simple when they run while hiding surprisingly complex systems underneath. Animation loops, interaction states, geometry, recursive functions, and rendering logic may be distributed across hundreds of lines of code.

Most learning tools separate code from behavior. Users read the implementation in one place, see the visual result somewhere else, and have to mentally reconstruct how everything connects. I built SketchTrace to connect three forms of understanding in one workspace:

What the code says → What it produces → How its systems relate

Rethinking the Experience

The original prototype could generate diagrams, but several issues made it difficult to use:

  • Complex diagrams quickly became overwhelming
  • Node-to-code navigation was unreliable
  • AI-generated Mermaid diagrams could fail
  • Preview loading lacked clear feedback
  • Too many instructions competed for attention
  • The project was not ready for public use

How might I help someone move naturally between code, behavior, and structure without making the interface itself more complicated?

I reorganized SketchTrace around three visible steps. The code editor stays on the left while the live preview and system map sit on the right, allowing users to compare implementation, output, and structure without changing screens.

The hierarchy follows the learning process: inspect the input, verify its behavior, understand its structure.

Testing With Real Creative Code

Simple UI examples did not demonstrate why structural visualization mattered, so I created four more demanding creative-coding studies. These examples include animation loops, recursion, geometry, pointer interaction, responsive behavior, and parallel systems — they became both learning content and stress tests for the product.

Showing Complexity Without Recreating the Code

My first diagrams tried to represent almost every meaningful function and relationship. They were technically complete — but difficult to understand. I reduced each example to roughly 11–13 essential nodes, prioritizing major systems and dependencies rather than implementation detail.

02

Connecting Structure Back to Source

A system map is only useful if users can understand where each concept actually exists in the program. I attached exact source ranges to rendered Mermaid nodes. Selecting a node now automatically:

  • opens the JavaScript tab
  • highlights the relevant source range
  • scrolls it into view
  • focuses the editor immediately

This became the core bridge between visual explanation and actual implementation.

03

Making AI Reliable Enough for a Learning Tool

AI-generated Mermaid syntax was not always valid. When generation failed, the visualization could disappear or expose syntax errors directly in the interface. I added multiple layers of protection:

  • Mermaid validation before rendering
  • output sanitization
  • cleanup of temporary error elements
  • structural fallback diagrams when AI output fails
  • manually verified diagrams for built-in examples

The four included studies therefore load instantly without requiring AI. AI is reserved for the task where it adds the most value: interpreting code supplied or modified by the user.

The Final Experience

Users can now:

  • Load a creative-coding example or paste their own code
  • Run it immediately in a live preview
  • Generate a concise structural map
  • Click nodes to navigate directly to source code
  • Pan, zoom, and resize the workspace while exploring

Resizable panels allow users to emphasize whichever representation — code, behavior, or structure — is most useful at that moment.

Designing for Focus

Because SketchTrace is designed for extended periods of inspection, I wanted the interface to stay visually quiet. I used restrained neutral colors, a low-saturation green background, Maven Pro typography, and subtle glass-like panels so the interface supports the code and artwork rather than competing with them.

Resizable cards give users control over which layer of the system they want to inspect.

What I'd Test Next

The next phase would focus on real learners rather than adding more features. I would test whether SketchTrace helps creative-coding learners:

  • locate important functions faster
  • explain unfamiliar sketches more accurately
  • understand relationships between systems
  • navigate between visual behavior and implementation with less effort

The most important future metric is not how many diagrams users generate. It is whether they understand unfamiliar code better after using one.
